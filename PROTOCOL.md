# Remote Terminal — Wire Protocol

All three components speak this protocol. Transport is a single **WebSocket**
connection per client. Every application message is a **UTF-8 JSON object** with
a `type` field. Terminal payloads are carried as UTF-8 strings inside JSON
(base64 is *not* used, to keep the slice simple and debuggable).

## Roles & rooms

A client declares its role and room via the WebSocket URL query string:

```
ws://<host>:<port>/?role=agent&room=<TOKEN>
ws://<host>:<port>/?role=phone&room=<TOKEN>
```

- `role` — either `agent` (the Windows machine) or `phone` (the Android app).
- `room` — a shared secret string that pairs one agent with one phone. Think of
  it as a pairing code. In the vertical slice it doubles as the only auth.

The server keeps a table of rooms. Each room holds at most one `agent` and one
`phone`. A second client of the same role replaces the previous one.

## Messages

### Server → client (control)

```jsonc
{ "type": "welcome", "role": "agent", "room": "abc123" }
{ "type": "status",  "peer": "connected"    }   // the other side joined
{ "type": "status",  "peer": "disconnected" }   // the other side left
{ "type": "error",   "message": "room full" }
```

### phone → agent (relayed through server)

```jsonc
{ "type": "input",  "data": "ls -la\r" }        // raw keystrokes, incl. \r for Enter
{ "type": "resize", "cols": 120, "rows": 30 }   // terminal geometry
```

### agent → phone (relayed through server)

```jsonc
{ "type": "output", "data": "PS C:\\> ls\r\n..." }   // raw PTY bytes as UTF-8
{ "type": "exit",   "code": 0 }                       // shell terminated
```

## Relay behaviour

- The server never inspects `input`/`output`/`resize`/`exit` — it forwards them
  to the room peer verbatim.
- `welcome` and `status` are generated by the server.
- If a message arrives with no peer present, it is dropped (the sender learns
  the peer state from `status`).

## Notes / non-goals for the slice

- No TLS in the slice (`ws://`). Production should use `wss://` + real auth.
- The phone renders `output` as text with basic ANSI handling; it is not a full
  terminal emulator yet.
